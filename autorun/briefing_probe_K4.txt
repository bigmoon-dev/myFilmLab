■ 背景（为什么是这四项）
v9 的选择器落底色 + 屏幕显示 NTR 已判定为交付级 BUG，必须修。
根因：官方"当前模式"单一状态变量同时喂三个消费者——
  捕获管线（照片内容）/ Color 选择器落点 / 屏幕模式显示。
v8/v9 供了捕获 → 选择器与显示坏；v7 反之。同一变量两头不可兼得。
v10 = 平时停在 DUO 家族（显示/选择器全对，预览走 v7 手法直写主拷贝），
检测到半按 → 官方链落底座（照片对）→ 拍完归位 DUO。
本探针拿齐 v10 定案所需的全部事实（含备选架构的存亡判据）。

■ 前置
1. 卡上 \fpSup.BIN = 原版 USB shell 版（监视任务绝不可在）；AutoRun.txt
   不动；冷启动
2. fpsh 通；电池充足；纪律照旧：命令单发 / hex 带 0x / 10-15s 超时 /
   禁 prom/adj/fwup / 禁读 0x2E030000+ / 卡死=拔电池+usbipd detach/attach
3. menu 序号域（v8.1 修正版——旧 K3 简报里 "5=NTR" 已作废勿用）：
   0=STD 2=NTR 11=MONO 14=DUO(归位)
4. 变体域（主拷贝字节，按 v9 g_looks 顺序）：R1=0x18 OR1=0x19 YE1=0x1A
   YG1=0x1B G1=0x1C G2=0x1D B1=0x1E B2=0x1F P1=0x20 M1=0x21
   （K4-1 第一步会实测校准一个非 R1 变体的真实字节）

────────────────────────────────────────────────────────────
■ P0 注入通路摸底（5 分钟）
────────────────────────────────────────────────────────────
docs_SHELL_COMMANDS.md 在案但从未实机调用过的三条注入通路，先摸底：
  ./host/fpsh device rc            # 无参=状态？（记录输出原文）
  ./host/fpsh device rc s1         # 预期：取景器出现 AF/AE 动作=半按生效
  ./host/fpsh device rc up         # up=释放？（观察 AF 解除）
若 rc 无效，降级试：
  ./host/fpsh key                  # 无参常打印 usage——记录原文后按语法试半按
判读：找到一条"按住=半按生效、释放=解除"的稳定通路，后续 K4-2/K4-4 用它。
注意：注入会触发真实 AF——镜头朝远处即可；本节全程不碰 S2（不拍）。

────────────────────────────────────────────────────────────
■ K4-1 变体记忆（2 分钟）
────────────────────────────────────────────────────────────
Color 键物理选 DUO，翻到一个非 R1 变体（记名字，如 B1）
  ./host/fpsh mem get 0xC31F8914,0xC31F8914,    # 校准该变体真实字节
  ./host/fpsh menu SetColorMode 2               # 落 NTR（取景变 Neutral）
  ./host/fpsh menu SetColorMode 14              # 归位 DUO
  ./host/fpsh mem get 0xC31F8914,0xC31F8914,
判读：读数=刚才变体字节 ⇒ 记忆保持（v10 拍完归位变体不丢）
      读数=0x18 ⇒ 固定回 R1（v10 需另寻变体直写字段，或接受拍完回 R1）

────────────────────────────────────────────────────────────
■ K4-2 半按可读状态位（10 分钟，注入刺激 + 小窗 diff × 3 轮）
────────────────────────────────────────────────────────────
候选窗（各 512KB，控制块富集区；避开 13MB 全堆——usbipd 重试风暴之鉴）：
  窗 A：0xC31A0000 +0x80000   （模式管理器区，0xC31AC51C 所在）
  窗 B：0xC3400000 +0x80000   （{flag,mode} 记录 / ADJ 参数区）
每轮 n=1..3：
  mem save \S1a_n.bin C31A0000,,80000
  mem save \S1b_n.bin C3400000,,80000
  <注入半按，保持>
  mem save \S1A_n.bin C31A0000,,80000
  mem save \S1B_n.bin C3400000,,80000
  <释放>
（大文件纪律：retries=0，10-15s 超时单发；卡死按老规矩复位续跑）
离线判读：三轮中"随 S1 稳定翻转、与时间噪声可分"的位 = 候选。

【关键复验——注入 ≠ 物理】找到候选位后：
  人手物理半按（另一只手/第二终端）：
  ./host/fpsh mem get <候选地址>,<候选地址>,
  松开再读一次。物理半按也翻转 ⇒ K4-2 成立；
  只跟注入走 ⇒ 该位在事件层之下，物理快门不经此路——记失败+候选位清单回传。

────────────────────────────────────────────────────────────
■ K4-3 选择器高亮跟随（1 分钟，备选架构 Color-flip 存亡判据）
────────────────────────────────────────────────────────────
  ./host/fpsh menu SetColorMode 2      # 制造 v9 同款状态（真身=NTR）
  按 Color 打开选择器 → 高亮应在 NTR（即 v9 的 BUG 现象复现）
  保持选择器打开，发：
  ./host/fpsh menu SetColorMode 14
  观察：①高亮跳到 DUO？②选择器崩溃/自动退出？
  关闭选择器 → mem get 0xC31F8914（最终停在谁）
判读：高亮跟随 ⇒ Color-flip 备选成立（平时 v9 态、检测到选择器开则归位）
      不跟随/崩溃 ⇒ 备选出局，v10 为唯一修复路线

────────────────────────────────────────────────────────────
■ K4-4 拍摄活动信号（5 分钟，v10 "拍完归位"的 shot-done 触发）
────────────────────────────────────────────────────────────
  ./host/fpsh status get is_recording           # 静止值（记录）
  ./host/fpsh status get app_current            # 应用态（REC/PLAY/MENU? 记录）
  ./host/fpsh status get app_lv_attribute       # 取景属性（记录）
  注入拍一张（记 SDIM 号）：<注入 s1> → 停 1s → <注入 s2/push> → <释放>
  立即连发 5 次（间隔 ~1s，逐次记录）：
  ./host/fpsh status get is_recording
  可选：./host/fpsh recstate stillsavewai       # 阻塞至存卡完成？（记录体感耗时）
判读：0→1→0 翻转 ⇒ shot-done 信号成立（后续 diff 定位底层变量进 v10）
      不翻转 ⇒ v10 降级用定时归位（全按后 3-5s，连拍期间顺延）
  （app_current/app_lv_attribute 为 v11 L1 面板的状态输入——面板需知
    REC/PLAY/菜单态；顺便记录播放态下这三值的变化，Color 键翻两张即回）

────────────────────────────────────────────────────────────
■ K4-5 预览合成语义（2 分钟，v10 预览路径存亡——新增，替代轴直写考古）
────────────────────────────────────────────────────────────
背景：v7 的"轴直写 ADJ"源码已随 v8 覆盖丢失，md_* 六份差分实证轴值
不在 0xC31B32BC 结构内。新预想路径 = 官方 setter 写宿主槽轴 + 直写
master 换色，若管线按"master 色 + 官方当前模式槽轴"合成渲染即成立。
  Color 键物理选 DUO.R1
  ./host/fpsh menu SetColorModeSaturation 4    # 观察①：取景=R1味+高饱和？
  ./host/fpsh mem set 0xC31F8914 0x00000005    # 直写 master=NTR
  观察②（关键）：取景 = NTR 色 + 饱和+4 仍在？
  ./host/fpsh mem get 0xC31F8914,0xC31F8914,   # ×2 间隔 3s：master 被推回？
  还原：menu SetColorModeSaturation 0；Color 键物理重选 DUO.R1
判读：②=是 ⇒ v10 预览 = master 直写 + 宿主槽轴 setter，零考古
      ②=色变轴失 ⇒ 轴不随官方槽走 → 需轴内存差分探针（窗 B 同法，
      axis 0 vs 4 各存一份）作为追加项
  注意顺序敏感性：若先写 master 再 setter，观察 setter 是否把色推回
  R1（记录：色/轴各自跟谁走）
