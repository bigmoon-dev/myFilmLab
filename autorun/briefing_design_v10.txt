■ 定位
修复 v9 的两个交付级 BUG（同根）：Color 选择器落底色家族 / 屏幕显示 NTR。
根因 = 官方"当前模式"单一状态变量喂 捕获+选择器+屏幕显示 三消费者。
v10 = 平时官方状态停在 DUO 家族（显示与选择器原生正确），仅在快门窗口
经官方链落底座（照片正确），拍完归位。预览走直写（v7 手法）。

■ 四态状态机（监视任务内部意图变量 intent 为第一输入，master 为第二输入）
  IDLE（常态）
    官方 = 宿主变体（用户当前 DUO 变体）。预览 = 直写 master=底色 enum +
    五轴写入宿主变体槽（官方 setter，顺序：先轴 setter 后 master 直写，
    顺序敏感性以 K4-5 实测为准）。名槽 = DuoTone 家族副本写当前配方名
    （UI 标签与 EXIF 同源）。轮询 K4-2 的 S1 位（轮询周期 10ms——检测
    延迟 + setter 链 ~100ms 须落在人的半按→全按窗口内）。
  COMMIT（S1 位出现且 IDLE）
    官方链落底座：SetColorMode(底座 menu 序号) + 五轴 setter（v8/v9 已
    验证的捕获正确链，一个字节不动）。轴写的是底座槽，与宿主槽互不污染。
  SHOOT（全按，无需检测 S2——捕获自然发生）
    等 shot-done：K4-4 的 is_recording 位（或降级定时 3-5s，连拍期间
    顺延——定长时间内再来 S2/全按信号则重置计时）。
  RETURN（shot-done 或超时）
    SetColorMode(14) 归位 DUO → 立即直写 master 恢复预览色（把"归位推
    回原厂色"的可见窗口压到最短）→ 进入 suppress 窗（见护栏）。
    变体恢复语义按 K4-1：记忆保持=天然回宿主；固定 R1=接受或另寻变体
    字段直写（K4-1 结果定，另立小探针）。

■ 状态机护栏（v8 现行逻辑的自冲突修复——v10 最大改造点）
  现行逻辑见 master 进变体域即视为"用户选择"→ settle → apply。v10 的
  RETURN 也让 master 进变体域 → 会被自己吃掉。改法：
    - RETURN 后置 suppress 标志；master 离开变体域再回来，或用户真实
      选择事件（选择器打开信号 / 变体值变化 ≠ 宿主值）才清标志重武装。
    - IDLE 期间 master 多数时刻=底色 enum（我们的预览直写），"变体域"
      不再是"用户在选择"的可靠信号——一切以 intent + 事件为准。
    - 自愈保留：官方 UI 重推（同值）→ 重写预览（v7 语义）。

■ 名槽（DuoTone 家族回归）
  五表族实证矩阵照搬 gen_looks.py 框架，底座换成 DuoTone 串：
  窗口 8B（"DuoTone\0"）→ 配方名 ≤7 字符断言保持。现行十名最长 SEPIA2=7
  恰满窗 ✓。变体切换时重写（单串全家族共享是已知化妆品限制，v11 L1
  面板解决全名显示）。

■ K4 分支矩阵（探针结果 → 设计动作）
  K4-1 记忆保持  → RETURN 免补丁；固定 R1 → 宿主≠R1 时接受回 R1（或加
                   变体字段直写小探针）
  K4-2 S1 位成立 → COMMIT 触发落定（物理复验必须过）；失败 → 事件层
                   hook 重评 / 转 Color-flip（K4-3 若成立）
  K4-3 高亮跟随  → 仅决定备选路线存亡，主路线不依赖
  K4-4 is_recording 翻转 → RETURN 触发落定；失败 → 定时归位
  K4-5 色+轴合成 → 预览路径落定（master 直写+宿主槽轴）；失败 →
                   追加轴内存差分探针（窗 B 同法）

■ 已入库事实（防重考）
  - md_* 六份差分（0xC31B32BC 结构 × axis 0/4 六态）完全一致：轴值
    不在该结构内——v7 轴直写地址不可由该素材恢复。
  - menu 序号域 v8.1 修正版：NTR=2（旧 K3 简报的 5 是作废值=CINE）。
  - shell 命令表（M_1.bin 实字节）复核：key/device/status/recstate/
    event/gui 处理器地址与 docs_SHELL_COMMANDS.md 逐条一致。
  - 固件字面量：key S1OFF / key S2 / HST_HalfPressed——S1 是一等状态。

■ 模拟门增补（simulate_load.py）
  1) 四态状态机断言：注入 S1 位序列 → COMMIT 序列调用 → shot-done →
     RETURN 序列 + suppress 行为。
  2) 负控（新增）：无 suppress 的旧逻辑变体必须 FAIL 于"RETURN 被自吃"
     断言（把这次设计改造变成常驻回归）。
  3) 名槽断言换 DuoTone 家族地址；S1 位/shot-done 位以桩变量模拟。
  4) 三件实物负控（v3/v5/v6）保持灵敏。
