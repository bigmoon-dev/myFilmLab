任务简报：探针会话 K1+K2（路线 B 基石取证）
日期：2026-10-15  交接：Design Agent  执行：相机侧（人 / WSL shell agent）

■ 目的（为什么要跑这一跑）
v7 预览层全功能完成，唯一残留：快门重推是同步链，照片内容=原厂。
路线 B（把配方写进重推源头）有两块基石，只能实机定：
  K1 = 五轴微调是否到达捕获管线（不只取景/ getter）
  K2 = 捕获链从哪个 RAM 变量取"当前模式"
两块都定 → v8 设计定案（重推越多越正确）；K1 倒了 → 回来重评。

■ 前置准备
1. SD 卡 \fpSup.BIN 换回 **原版 USB shell 版**（不是 v7——v7 的监视任务会
   干扰观测；我们要原厂行为+shell）。AutoRun.txt 不动。冷启动。
2. USB 连接，fpsh 通（ping OK）。电池充足。卡内剩余空间 ≥ 200MB。
3. 纪律（老规矩）：
   - 命令**单发**，hex 值一律带 0x 前缀，10-15s 超时，超时重发 ≤2 次
   - 每条 mem set 前先 mem get 记录原值（写入对象全是 RAM，重启即还原；
     但记录原值=对照组）
   - 禁：prom / adj / fwup / sdcard format / fl delall；禁读 0x2E030000+
   - 卡死预案：拔电池（卡可留）→ usbipd detach/attach → 断点续跑
4. 拍照判读：每张记录 SDIM 编号；JPG 直接判读（饱和/影调差异肉眼可见）。
   建议备拍两张基线：STD 原厂 1 张、DUO.R1 原厂 1 张。

■ 已知现场（来自 dump 三态测绘，DUO 态实测值）
  0xC31F8914 = 0x18   0xC2F19D44 = 0x18   0xC3413B7C = 0x18
  0xC3413F90 = 0x18
  0xC3414D08 = 0x01   0xC3414D0C = 0x18   （{flag,mode} 记录1）
  0xC3414D10 = 0x01   0xC3414D14 = 0x18   （{flag,mode} 记录2）

────────────────────────────────────────────────────────────
■ K1：五轴是否进捕获（STD 态）
────────────────────────────────────────────────────────────
K1-0. Color 键确认当前 = Standard；拍基线 1 张（记 SDIM 号）
K1-1. ./host/fpsh menu SetColorModeSaturation 4
K1-2. ./host/fpsh menu SetColorModeSaturation        （getter 应读回 4）
K1-3. 拍照 1 张（记 SDIM 号）
K1-4. ./host/fpsh menu SetColorModeSaturation 0      （还原）
判读：K1-3 张 vs 基线张——饱和度肉眼变化明显 ⇒ K1 成立；
     无差别 ⇒ K1 不成立（回传，重评路线）。

────────────────────────────────────────────────────────────
■ K2：捕获链模式源（DUO.R1 态）
────────────────────────────────────────────────────────────
K2-0. Color 键选 DUO.R1（glyph 显示 R1）；拍基线 1 张（记 SDIM 号）
K2-1. 对照组（预期：取景变、照片不变——证明捕获不听 master）：
      ./host/fpsh mem get 0xC31F8914,0xC31F8914,
      ./host/fpsh mem set 0xC31F8914 0x00000005      （主拷贝改 NTR）
      → 屏幕取景应立即变 NTR 味（不变=记录异常）
      → 拍照 1 张（记 SDIM 号；预期照片=原厂 R1）
K2-2. 候选1（{flag,mode}记录1 的 mode）：
      ./host/fpsh mem get 0xC3414D0C,0xC3414D0C,
      ./host/fpsh mem set 0xC3414D0C 0x00000005
      → 观察屏幕（取景/标签有无变化）→ 拍照 1 张
      → ./host/fpsh mem get 0xC3414D0C,0xC3414D0C,   （被重推回 0x18 了吗？）
      ./host/fpsh mem set 0xC3414D0C 0x00000018      （还原）
K2-3. 候选2（记录2 的 mode）：同流程操作 0xC3414D14。
K2-4. 候选3（独立字）：同流程操作 0xC3413F90。
K2-5. 设置层直达：
      ./host/fpsh setting get pic_color_mode 0        （记录当前值）
      ./host/fpsh setting set pic_color_mode 0 5      （设置改 NTR）
      → 观察屏幕（标签/glyph 跟谁走）→ 拍照 1 张
      → 还原：用 Color 键物理重选 DUO.R1（比 setting set 回写更稳）
判读（每条记录三样：屏幕反应 / 照片内容 / 写后回读值）：
  · 照片变 NTR 味的那条 = 捕获链模式源（K2 正解）
  · 写后回读被改回 0x18 = 该变量是下游（从拷贝），重推源在别处
  · 全部无效（照片全原厂）= 捕获链不读 RAM 变量 → 回传，路线降级重评

────────────────────────────────────────────────────────────
■ 收尾
- 五轴已归零（K1-4）；pic_color_mode 物理重选还原（K2-5）；
  mem set 过的候选全部回写 0x18（K2-2/3/4 已含）
- ./host/fpsh setting get pic_color_mode 0  确认 = DUO.R1 对应值
- 安全弹出 USB → 拔卡 → 全部 SDIM 照片拷回 D:\work\fp\dump\probe_K1K2\

■ 回传格式
1. 每条命令的实际应答（尤其 getter 读回、写后回读）
2. SDIM 编号 ↔ 实验步对照表 + 每张照片的一句话判读
3. K1 结论（成立/不成立）+ K2 命中地址（或"全部无效"）
4. 屏幕侧观察：哪个写入改变了标签/glyph（=UI 侧变量，与捕获源可能不同）
